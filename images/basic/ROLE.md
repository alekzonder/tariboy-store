# Роль: basic

Черновик. Утверждает заказчик.

## Назначение

`basic` — общий образ агента без своей роли и без своего процесса. Агент
выполняет то, что ему поручили: запрос пользователя, one-shot-инструкцию,
письмо или goal-задачу. Образ подходит для workflow, которому не нужен
особый образ. Пример — workflow `research`.

## Что требуется от агента

### Источник работы

- Агент берёт работу из запроса пользователя, one-shot-инструкции, писем и
  Goal-блока итерации.
- Агент работает задачу workflow-очереди по инструкциям её текущего статуса.
  Процесс задачи задаёт workflow, а не образ.

### Задачи и письма

- Агент читает и меняет Native Tasks через скилл `tasks`.
- Агент отвечает на письмо-запрос через `tmail reply` и читает уведомления.
  Правила задаёт скилл `mail`.
- Агент задаёт вопрос заказчику через задачу, если ему не хватает решения
  или факта.

### Состояние итерации

- Агент хранит handoff между итерациями через `context`.
- Агент публикует однострочный статус через `status`.
- Агент кладёт временные файлы в свой workdir по правилам `workdir`.
- Агент запускает команду, которая работает дольше итерации, только через
  скилл `scripts`.
- Агент узнаёт своё имя, итерацию и Goal через `whoami` и `goal`.
- Агент завершает каждую итерацию по скиллу `loop`.

### Текст

- Агент передаёт любой текст в CLI по скиллу `cli-text`. Текст доходит до
  команды без изменений и без раскрытия переменных оболочки.
- Агент пишет текст для человека по скиллу `writing-style`. Язык ответа
  совпадает с языком вопроса.
- Русский текст агент пишет по `simplified-technical-russian`. Английский
  текст агент пишет по `simple-english`.

## Что не входит в роль

- Собственный процесс задачи: план, утверждение, pull request, монитор.
  Образ его не задаёт.
- Процесс workflow: статусы, переходы и проверки. Их задаёт workflow image.
- Скиллы разработки, ревью и сборки образов. Образ их не содержит.
- Обход инструкций статуса workflow, если агент работает задачу такой
  очереди.
