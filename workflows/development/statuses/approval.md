# Approve the plan

The developer has written a plan for this task. Read it in the task's `plan`
artifact: it explains how the solution works, the ordered steps, how the
change will be verified, and its limitations. An open question, if any, is at
the end of the plan.

Choose one outcome:

- `approved`: the developer implements the plan as written, in its own branch
  and worktree, and opens a pull request. The task then waits while the
  pull request is reviewed; the developer never merges it.
- `changes_requested`: the plan goes back to the developer, who revises it and
  sends a new version here. Say what to change, and answer any open question,
  in the message of this outcome; the developer works from that message.

Approve only the plan you read. If the scope changes later, request changes
so that a new plan is written.
